# 매일 운영과 복구

## 지속 실행

환경 설정만 저장하면 실행기가 시작되는 것은 아닙니다. 인증과 승인 콘텐츠 준비 후,
지속 실행할 수 있는 개인 서버 또는 사용자 PC에서 아래 명령을 실행합니다.

```sh
cd /workspace/FaktaNuWorld
export YOUTUBE_CHANNEL_ID='확인한_채널_ID'
export YOUTUBE_TOKEN_FILE='/안전한/경로/token.json'
.venv/bin/python -m faktanu.pipeline worker --config pipeline.toml --upload --interval 300
```

작업용 클라우드 환경의 종료·정지는 워커도 중지합니다. 매일 무인 운영에는
프로세스 감독자와 영속 디스크가 있는 운영 호스트가 필요합니다.
이 구현은 외부 호스트 배포나 시스템 서비스 등록을 자동으로 수행하지 않습니다.
Linux에서는 systemd 등으로 위 명령을 관리하거나 cron으로 `daily --upload`를 5분마다 호출할 수 있습니다.
cron의 호스트 시간대는 무관하며 프로그램이 Europe/Stockholm으로 실행 시각을 판단합니다.
워커와 cron 중 하나를 운영 방식으로 선택하고, `state/`를 같은 로컬 영속 디스크에 보관하세요.

`SIGINT`/`SIGTERM`은 진행 중인 작업을 마친 뒤 워커를 종료합니다.
현재는 하나의 채널과 운영 호스트를 지원합니다. SQLite를 네트워크 파일시스템에서 공유하거나
여러 호스트에서 복제해 실행하지 마세요. 여러 호스트 운영에는 공유 데이터베이스가 필요합니다.

## 콘텐츠 운영

초기 큐는 초안 3편이며 자동으로 보충되지 않습니다.
출처 원문 대조 → 스웨덴어 검수 → `approved: true` → 비공개 업로드 → YouTube Studio 재생·검토 → 공개 순서입니다.
대본 승인 여부는 공개 여부가 아닙니다. 일일 실행기는 항상 비공개 업로드합니다.
`render`/`daily` 미리보기 결과는 매번 별도 폴더에 생성되며 업로드된 콘텐츠를 소비하지 않습니다.
미리보기 출력과 오래된 영상은 운영자가 검토 후 정리해야 합니다.

## 상태와 중복 방지

`state/daily.sqlite3`에는 날짜별 콘텐츠 ID와 `pending`/`uploaded` 상태가 기록됩니다.
날짜와 콘텐츠 ID 각각에 UNIQUE 제약이 있어 동시 실행에서도 업로드 작업을 한 번만 획득합니다.
기존 개별 업로드의 `state/<콘텐츠 ID의 SHA-256>.json` 기록도 큐 선택 시 확인합니다.
큐 경로와 출력 경로는 설정 파일 기준으로 해석합니다. 대본은 생성 시 출력 폴더에 복사하여 보존합니다.
인증 사전 검사 실패나 영상 생성 실패는 날짜를 소비하지 않으므로 설정을 수정한 뒤 다시 실행할 수 있습니다.

업로드를 시작한 뒤 실패하면 `pending`을 유지합니다. YouTube가 실제로 받았는지 불명확하므로
자동 재전송하지 않습니다. 다음 실행은 `already_claimed`가 되며 상태를 먼저 확인해야 합니다.

```sh
.venv/bin/python -m faktanu.pipeline status --config pipeline.toml
```

복구 전에 워커/cron을 중지하고 `state/`를 백업하세요.
YouTube Studio에서 제목과 업로드 시간으로 원본 영상의 존재 여부를 확인합니다.
업로드됐다면 YouTube 영상 ID를 JSON 기록과 SQLite 행에 맞춰 기록하고 `uploaded`로 정리합니다.
업로드되지 않았음을 확인했을 때만 해당 `pending` 행과 개별 pending JSON을 제거하여 재시도합니다.
단순 연결 오류만으로 미업로드를 판단하거나 상태 파일 전체를 지우지 마세요.
현재 복구는 수동이며, 연결이 복구되면 언제든 같은 날짜 작업을 다시 확인할 수 있습니다.

콘텐츠가 없으면 `queue_empty`, 시각 전이면 `not_due`, 처리된 날짜면 `already_claimed`를 반환합니다.
워커 실패 로그는 인증값 노출을 막기 위해 오류 유형만 기록합니다.
실패 알림 및 분석 지표 수집은 후속 구현이며, 현재 운영자가 로그와 상태를 확인해야 합니다.
