# 설계와 구현 순서

## 현재 기술 구현

JSON 콘텐츠 → 검증 → FFmpeg 1080×1920 / 30fps / H.264 + AAC → 검수 → OAuth 채널 확인 → YouTube 업로드.
렌더링 결과 옆 JSON에는 승인 상태, 음성 사용 여부, 영상 SHA-256을 저장합니다.
업로드 직전 영상 변경과 콘텐츠 ID 중복을 확인합니다. FFmpeg 인수는 셸을 거치지 않습니다.
매니페스트는 로컬 작업 파일이며 악의적 변경을 방지하는 보안 서명은 아닙니다.

## 내용 구현

주제와 언어는 스웨덴어 세계 상식으로 확정했습니다. 독자층과 구체적인 편집 기준은 다음 단계에서 정합니다.
각 콘텐츠는 출처, 사실 확인 날짜, 원문 주장과 대본, 미디어 사용 권한을 관리해야 합니다.
주제 수집과 사실 검증은 분리하고 생성형 모델 결과를 사실의 근거로 사용하지 않습니다.
짧은 훅, 핵심 사실, 맥락, 구독 안내로 구성하고 자막 가독성과 음성 타이밍을 검수합니다.
NASA 예제는 회전 주기와 태양일의 차이를 명시합니다. 출처 재확인은 운영 전 필요합니다.

## 설명과 설정 구현

채널 ID, 콘텐츠 언어, 업로드 시각과 시간대, 공개 정책, 음성 공급자를 설정 파일로 통합하는 단계입니다.
사용자 선택에 따라 비공개 업로드 후 검토하고 공개하는 방식입니다. 기본값은 private이며, 공개 전환은 YouTube Studio에서 진행합니다. 명시적 환경 변수를 제공합니다.
Google 비밀키와 토큰은 소스 및 CI 로그에 저장하지 않습니다.
로컬 refresh token을 읽는 OAuth 라이브러리는 실제 파일 내용이 필요합니다.
HTTPS 프록시 전용 placeholder secret은 토큰 파일의 대체재가 아닙니다.

## 매일 운영 단계 — 아직 활성화되지 않음

스케줄러는 Europe/Stockholm 시간대와 일광절약시간을 고려합니다. 업로드 시각은 사용자가 정해야 합니다.
큐에서 승인된 콘텐츠 하나를 선택하고, 렌더링 → 기능 검사 → 업로드 → 결과 기록 순서로 실행합니다.
중복 콘텐츠 키, 날짜별 실행 기록, 공유 DB 잠금, 실패 알림, API quota 확인을 추가해야 합니다.
GitHub Actions를 사용할 경우 보안 secret 전달과 영속 상태 저장을 먼저 구현합니다.
현재 CI는 테스트만 실행하며 예약 업로드나 이메일 발송은 하지 않습니다.
자동화 전에 OAuth 연결, 실제 비공개 업로드, YouTube 재생, 제목·설명·자막을 끝까지 검증해야 합니다.

## 검증 범위

로컬 단위 테스트와 실제 렌더링을 제공하며 업로드에는 실제 채널 인증이 필요합니다.
공급자 미정으로 TTS 호출은 구현하지 않았습니다. 현재는 사람이 제공한 녹음 파일을 사용합니다.
콘텐츠 완전 자동 생성, 예약 실행, 분석 지표 수집은 후속 단계입니다.
